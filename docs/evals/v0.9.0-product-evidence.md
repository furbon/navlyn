# v0.9.0 measured product evidence

## Warm MCP execution

Measured on 2026-10-04, Windows 10.0.26200, SDK 10.0.401, Debug build, the same FuzzyDiscoveryFixture workspace, full profile, one warmup and three measured rounds in one persistent MCP session. These are small local measurements, not general performance guarantees.

| Tool | v0.8.7 mean | v0.9.0 mean |
| --- | ---: | ---: |
| file outline | 27.7 ms | 23.3 ms |
| navigation | 859.7 ms | 15.7 ms |
| read | 19.3 ms | 15.7 ms |
| workspace summary | 8,719.3 ms | 25.3 ms |

Summary discovery previously included generated validation artifacts. Pruning those trees fixes the reported repository facts as well as reducing elapsed time/output. All 12 measured calls succeeded, with valid JSON and no truncation.

## Discovery and transport

The 25-tool legacy tools/list payload changed from 118,940 characters in v0.8.6 to 113,329 in v0.9.0 (4.7% smaller), including the new targetFramework argument. Useful schema constraints remain. Null fields omitted by the serializer are no longer falsely required in advertised output schemas. Text result JSON is compact. Raw legacy initialize and SDK 2 discovery-first clients both enumerate the same tool surface.

SDK upgrade source: [MCP C# SDK 2.0 release](https://github.com/modelcontextprotocol/csharp-sdk/releases/tag/v2.0.0).

## Fixed live comparison

Codex CLI 0.160.0, GPT-5.5, high reasoning, identical source/task prompts and isolated pristine workspaces. Three fixed tasks, one attempt per condition; the Navlyn condition explicitly used its MCP tools, while baseline used ordinary reading/search/.NET tools. The fixture has twelve lines, two overloads and interface/direct callers. Correctness checks include exact member/caller identity and an integer-overload-only edit; both edit conditions preserved the string overload and callers.

| Task | Condition | Correct | Time | Tool calls | MCP calls | Captured output chars | Input tokens / cached |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| binding | Baseline | yes | 24.6 s | 4 | 0 | 4,728 | 42,140 / 28,800 |
| binding | Navlyn | yes | 36.4 s | 6 | 6 | 43,619 | 162,627 / 137,216 |
| interface | Baseline | yes | 15.6 s | 2 | 0 | 3,811 | 41,999 / 27,776 |
| interface | Navlyn | yes | 56.4 s | 8 | 8 | 86,855 | 219,223 / 189,184 |
| edit | Baseline | yes | 29.0 s | 6 | 0 | 8,217 | 72,900 / 57,216 |
| edit | Navlyn | yes | 48.0 s | 7 | 3 | 56,045 | 166,881 / 120,832 |

All six tasks were correct. No wrong-target edit occurred. Navlyn took longer and consumed more input/output on this tiny, readily readable fixture. This experiment supports functional usefulness, but provides no speed/cost advantage and no evidence about large-repository agent accuracy. Prefer one focused question and stop once answered; discovery/schema and repeated result context remain a product cost worth improving. Do not turn these three tasks into a mandatory campaign or a scored release gate.

Initial attempts with the configured app model name were rejected by the CLI before task execution; an old CLI version and retired model name also failed initialization. Those setup failures are excluded from task correctness and latency. The CLI was updated and GPT-5.5 was explicitly selected identically for the six completed attempts. No claims are made for unexecuted models.

## External-package corpus

The pinned local public-package corpus checked seven .NET 10 cases: modern C#, platform-specific multi-target Serilog calls, transitive constructor reads, direct DLL references, and a 120-file source fixture. Six initially passed. The remaining case was classified as expected-pe-absent because migrated test data incorrectly expected a nonexistent Serilog net10 asset; Serilog 4.2.0 actually selects lib/net9.0. Only that case was corrected and rerun successfully. This was an expectation defect, not a product navigation failure. Exact overload identity, implementation hashes, provenance and body selection remain checked.

Generated JSON/JSONL/TRX/timing files stay in ignored artifacts directories; this document records the durable outcome.

# v0.8.2 real-task campaign

The campaign uses frozen tasks from four development repositories and two sealed holdout repositories. Each repository contributes a bug fix, feature and investigation. The final comparison has two independent A/B/C repetitions per task (108 primary attempts), six candidate skill-off development attempts and twelve Sol/medium B/C sentinel attempts. Development observations and excluded pilots remain separate from final scores.

The task prompt, base commit, hidden oracle hash, model/effort, budgets, installed package and skill identities, tool inventory, and runner input must be frozen before an attempt. The private oracle, actor trace, checkout and credentials stay outside the published campaign manifest. One task/repetition block has identical model, effort, base, prompt, oracle and condition hashes across arms; the arm-specific input selects ordinary tools alone (A), released v0.8.1 (B), or candidate v0.8.2 (C). The independent scorer receives only a closed actor workspace and its immutable worker ID. A passing hidden test still needs source-diff review before task acceptance.

The committed [manifest schema](v0.8.2-real-task-campaign.schema.json) describes the campaign registration. Each attempt binds a frozen [score plan](v0.8.2-real-task-score-plan.schema.json) containing the task/oracle hash and exact private adapter bytes. `scripts/run-real-task-eval.ps1` provides `Register`, `Preflight`, `Run`, `Resume`, and `Aggregate`; `scripts/score-real-task-eval.ps1` calls the registered private scoring adapter after verifying the actor report, oracle and adapter hashes. `Register` and `Preflight` do not launch a model, and a matching passed preflight receipt is required before `Run`. `Resume` skips only completed attempts whose identities and retained outputs still match and preserves failures or incomplete attempt directories; a justified retry receives a new attempt ID and stays in the launch denominator. The underlying isolated runner is responsible for actual model, filesystem, network, budget, process-tree and complete raw-trace enforcement. The wrapper never upgrades a mere actor completion to task success, and the score wrapper never marks behavioral success as independently accepted without diff review.

For a registered manifest under an owned ignored audit directory:

```powershell
./scripts/run-real-task-eval.ps1 -Action Register -Manifest <manifest.json> -OutputDirectory <owned-results>
./scripts/run-real-task-eval.ps1 -Action Preflight -Manifest <manifest.json> -OutputDirectory <owned-results>
./scripts/run-real-task-eval.ps1 -Action Run -Manifest <manifest.json> -AttemptId <attempt-id> -OutputDirectory <owned-results>
./scripts/run-real-task-eval.ps1 -Action Resume -Manifest <manifest.json> -OutputDirectory <owned-results>
./scripts/run-real-task-eval.ps1 -Action Aggregate -Manifest <manifest.json> -OutputDirectory <owned-results> -ScoreDirectory <owned-scores>
```

An operator-provided PowerShell scoring adapter accepts `-TaskId`, `-WorkerId`, and `-ScoreId`, returns one JSON object with matching `taskId`, `workerAuditId`, `scoreId`, `hiddenOracleSha256` and boolean `behaviorPassed`, and keeps oracle material outside actor mounts. The score wrapper fixes its adapter and oracle by SHA-256 and refuses to overwrite a score ID. It writes no private oracle content to the public report. `./scripts/test-real-task-eval.ps1` exercises the orchestration with a deterministic no-model runner and scorer; those synthetic outcomes are harness tests, never campaign evidence.

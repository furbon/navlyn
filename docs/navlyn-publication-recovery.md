# Exact-artifact NuGet publication

The protected `publish-nuget.yml` workflow accepts `normal` or `resume` and requires an explicit full reviewed main SHA. Both modes retain the existing `nuget-production` environment, Trusted Publishing, main-only dispatch and serialized publication group. `publish-nuget.ps1` remains a package dry-run inspector; its `-Publish` option refuses publication outside this workflow.

Normal mode validates and packs both packages, builds the setup bundle, and retains their exact bytes before publication. Internal real-task evaluation records are not publication assets or NuGet gates. Source validation in the protected workflow and release validation remain required. The setup ZIP's integrity manifest must identify the same source commit, and each included source file must match the checkout. The existing release-pack manifest stays `navlyn.release-pack.v1`; a separate `navlyn.publication-inputs.v1` manifest binds the fixed retained package and setup filenames and SHA-256 values.

Resume requires the original `input-run-attempt` and latest prior `latest-run-attempt` as canonical `runId:attempt` strings, the original immutable input artifact ID/service SHA-256, exact input manifest SHA-256, and latest immutable journal artifact ID/service SHA-256. The source SHA must still be the unchanged main checkout. Resume downloads retained bytes and never runs packing or setup generation. Missing, expired or ambiguous artifacts stop recovery.

The service adapter verifies repository/workflow/main/source identity, ended run attempts, immutable service digests and artifact creation within the owning attempt. It enumerates every publisher run and rerun for this source SHA. Only an explicitly completed, skipped publication step proves that an earlier attempt could not submit. Every other prior attempt needs a retained journal in the complete linear predecessor chain. An inventory reaching GitHub's filtered 1,000-result limit stops rather than accepting a truncated history. Unsupported/incomplete histories require operator investigation.

The workflow initializes the attempt journal before login, reauthenticates input bytes and the complete history before publication, then writes durable intent before each push. The journal is always retained separately from immutable inputs. A public package is skipped only after current NuGet certificate verification, explicit signed repository service-index verification and a canonical match of every original ZIP entry. Only the added `.signature.p7s` entry is allowed. Raw signed and unsigned hashes remain distinct.

A prior intent with absent indexing, unavailable service, interruption or uncertain acceptance never authorizes another push. The attempt remains blocked until its exact public bytes can be verified or an operator reconciles the service state. Polling is bounded; the implementation does not use `--skip-duplicate`. This conservative path can require a new protected resume dispatch after service propagation.

Run `scripts/test-publish-recovery.ps1` and `scripts/test-publish-orchestration.ps1` for credential-free synthetic coverage. `-LiveBaselineTrust -BaselinePackageRoot <absolute-directory> -BaselinePublisherArchive <absolute-zip>` additionally performs read-only trust and exact-content checks against the retained genuine v0.8.1 baseline and fresh public downloads. The directory contains `navlyn.0.8.1.nupkg` and `navlyn-mcp.0.8.1.nupkg`; the archive is the exact retained v0.8.1 publisher artifact checked by its pinned digest. Passing those checks is not evidence that a candidate release was published or that the protected workflow ran successfully.

Primary service contracts: [GitHub artifacts](https://docs.github.com/en/rest/actions/artifacts), [GitHub workflow attempts](https://docs.github.com/en/rest/actions/workflow-runs), [NuGet repository certificates](https://learn.microsoft.com/en-us/nuget/api/repository-signatures-resource), [NuGet verify](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-nuget-verify), and [signed repository service-index specification](https://github.com/NuGet/Home/wiki/Repository-Signatures-and-Countersignatures-Technical-Specification).

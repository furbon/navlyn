# v0.8.7 implementation and release plan

## Outcome

Publish both 0.8.7 tools after fixing cancellation throughout MCP execution and replacing the hour-long Windows validation pipeline with a short, useful development loop. Preserve existing public command meanings. The user authorizes implementation, environment changes, Git operations, authentication, publication, and continued work through 0.9.0.

## Work

1. Fix external process cleanup for deadline expiry, caller cancellation, blocked stdin, output reads, and process-start failure. Review direct and in-process cancellation, queue ownership, console restoration, and subsequent calls together.
2. Add focused regression coverage using a small real child process and existing fixtures; avoid large repository loads for transport assertions.
3. Add a process deadline to the common PowerShell harness, with process-tree cleanup and useful failure output. Replace string-built process arguments with ArgumentList.
4. Remove duplicate release checks, repeated full-workspace protocol calls, synthetic scoring from release gates, repeated package builds, and client installation checks unrelated to changed code. Keep inexpensive contract tests and one installed-package smoke.
5. Use one .NET 10 test execution on the primary OS, with a small CLI/protocol smoke on all three OSes. Keep unchanged .NET 8 package assets only until the 0.9.0 migration; do not spend a separate test lane on them.
6. Record the slowest existing tests and stages, then replace their expensive setup rather than extending timeouts. Target a primary CI job below ten minutes and secondary jobs below five minutes; report observed timings.
7. Add repeated cold/warm performance measurements with version, commit, SDK, OS, and comparable baseline metadata. Keep measurements small and separate from functional test repetition.
8. Pin Actions to full commit SHAs, retain useful logs/TRX/timings, and reconcile dependency PRs already incorporated in 0.8.6.
9. Update release identity, CLI/MCP cancellation documentation, development instructions, changelog, and runtime policy as needed. Publish exact tested artifacts, verify public packages, and create the annotated tag and GitHub release.
10. Review the entire change and surrounding behavior during planning, implementation, and release preparation: CLI/MCP/batch parity, workspace selection and freshness, output limits and schemas, installation, package contents, publication/recovery, CI conditions, and documentation claims. Investigate and fix newly discovered problems, including issues outside cancellation; do not treat the first repaired symptom as completion.

## Verification and execution order

Fix and run the focused cancellation tests first. Validate modified PowerShell scripts next. Run the shortened primary suite once after integration, and rerun only failures or tests affected by later edits. Build packages once in CI and publish the retained bytes. Publication and tag verification must not rerun source tests. Use no broad AI evaluation campaign for a transport maintenance release.

## Self-review

- Scope includes every adopted 0.8.7 recommendation and removal of unnecessary work, not just faster execution of the old pipeline.
- The timeout fix covers cancellation before start, during input/output, during execution, and during cleanup; tests prove process exit rather than only an error envelope.
- Changing tests to small fixtures must preserve their actual assertions; redundant assertions may be deleted when faster component coverage already proves them.
- Reduced runtime/OS repetition is intentional and user-authorized. .NET 8 backward-compatibility work is excluded.
- Existing publication identity checks remain useful; general-purpose scoring, repeated full loads, and redundant setup campaigns do not belong on every commit.
- Unknown defects are in scope across the product and delivery flow. Use code inspection, representative end-to-end calls, and targeted regression checks rather than an ever-growing general harness.

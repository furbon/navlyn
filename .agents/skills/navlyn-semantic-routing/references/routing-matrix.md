# Routing Matrix

Use this matrix when the first action is uncertain. A follow-up is allowed only when it answers a specific unresolved fact; stop when the stop condition is met. Conclusions remain bounded by the reported evidence.

| Task class | Activation decision | First action | Required inputs | Allowed follow-ups | Stop condition | Prohibited shortcut | Permitted conclusion | Prohibited conclusion |
|---|---|---|---|---|---|---|---|---|
| Approximate name | Activate if symbol identity could change the answer. | `navlyn_target` select. | Query; optional project and fuzzy hints. | Read selected candidate or navigate one relationship. | One candidate is sufficiently confident, or ambiguity is exposed. | Do not select among material alternatives by guess. | State candidate identity and confidence. | Claim a unique intent when selection is ambiguous. |
| Exact source position | Activate if semantic meaning at the location matters. | `navlyn_target` select for an anchor, or `navlyn_read` for bounded text. | Repository-relative file, line, and column. | Navigate or inspect bounded source for the same anchor. | The location resolves the needed fact. | Do not treat line text alone as symbol identity. | State source fact at that workspace location. | Generalize to all projects or frameworks without evidence. |
| Known-file outline | Activate only when semantic structure in a known file matters. | `navlyn_file_outline`. | Source-file path; project if needed. | Read one relevant declaration. | The file map identifies the needed member. | Do not outline as a substitute for ordinary reading. | Describe indexed declarations and relationships. | Claim the outline is the full file contents. |
| Source reading | Activate for one bounded semantic source view. | `navlyn_read`. | `candidateId` or exact position and a suitable view. | Outline or navigate if a specific fact remains missing. | The requested bounded source is returned. | Do not request broad file contents through a semantic tool. | Summarize returned source within its range. | Claim unreturned members or runtime behavior. |
| Definition | Activate when declaration identity or location matters. | `navlyn_navigate` operation definition. | `candidateId` or exact position. | Read the selected declaration. | Definition location resolves the question. | Do not use text search as semantic identity proof. | State indexed definition location. | Claim runtime binding or dispatch. |
| References | Activate when semantic reference sites matter. | `navlyn_navigate` references. | Target anchor; project/scope when useful. | Read selected sites or narrow scope. | Relevant sites are returned or limits explain incompleteness. | Do not treat partial search as exhaustive. | Report found sites and scope. | Claim no references exist beyond reported scope. |
| Callers | Activate for static incoming-call relationships. | `navlyn_navigate` callers. | Target anchor; scope for broad searches. | Read selected caller bodies or inspect impact. | Needed callers are found or truncation is understood. | Do not imply runtime invocation from a static edge. | Report static caller edges. | Claim a method runs in production. |
| Calls | Activate for calls made inside a containing member. | `navlyn_navigate` calls. | Target anchor. | Read the containing member. | Local call facts answer the question. | Do not widen local calls into repository-wide behavior. | Describe calls indexed for that member. | Claim a call executes on a particular path. |
| Implementations | Activate for static implementation relationships. | `navlyn_navigate` implementations. | Interface/base target anchor. | Read selected implementation. | Relevant implementations are identified. | Do not assume every implementation is discoverable. | State reported implementation links. | Claim runtime selection among implementations. |
| Type hierarchy | Activate when inheritance/interface shape affects the answer. | `navlyn_navigate` type_hierarchy. | Type anchor. | Read specific declarations. | The needed hierarchy facts are visible. | Do not infer runtime object type from hierarchy alone. | Describe indexed type relationships. | Claim a runtime instance uses a particular type. |
| Overloads | Activate when signature choice changes meaning. | `navlyn_target` select the intended overload. | Query plus project/kind constraints as needed. | Navigate definition or read candidate signature. | One overload is anchored or ambiguity remains explicit. | Do not choose by name alone. | State signature and selection evidence. | Treat same-name overloads as interchangeable. |
| Partial declarations | Activate when declarations may be split across files. | Target the symbol, then navigate definition or use outline. | Symbol query/candidate and project context. | Read relevant partial declaration locations. | All relevant returned parts are understood. | Do not assume one file contains the whole type. | Describe parts found in the selected project. | Claim undiscovered parts do not exist. |
| Multiple projects | Activate when project ownership/references affect results. | Target or focused tool with `project`/`projects`. | Project names/paths and symbol or domain input. | Repeat within another explicit project if needed. | Each in-scope project is represented. | Do not merge same-named symbols without project identity. | Attribute facts to reported projects. | Claim solution-wide coverage from one project. |
| Multiple target frameworks | Activate when compile context changes APIs or source. | Select the project/framework context on the focused query. | Project and relevant target-framework context. | Compare framework-specific results or inspect project facts. | Required framework variants are checked. | Do not treat one target as every target. | State the observed framework context. | Claim all builds behave identically. |
| Linked files | Activate when a file may compile under several projects. | Query with explicit project context. | Linked file path and project. | Compare the linked contexts that matter. | The relevant compilation context is identified. | Do not treat path identity as project identity. | State project-specific semantic facts. | Collapse distinct project symbols into one fact. |
| Generated code | Activate when generated source could distort semantic facts. | Focused tool with `excludeGenerated` as appropriate. | Target/query and generated-code policy. | Inspect generated evidence only when requested and relevant. | Generated/manual evidence is distinguished. | Do not call generated source hand-authored intent. | Label facts by generated status. | Infer author intent from generated output. |
| Workspace/project/package/MSBuild facts | Activate when workspace structure affects the answer. | `navlyn_workspace_summary` with a narrow profile/filter. | Optional project filters and needed graph facts. | Workspace status/refresh only for freshness; focused semantic tool next. | Needed project/framework/package facts are present. | Do not use as a routine preamble. | Report static loaded-workspace structure. | Claim build success or runtime configuration. |
| Diagnostics | Activate for compiler diagnostics already in the loaded workspace. | `navlyn_diagnostics` workspace, symbol, or pack mode. | Mode and compatible project/diagnostic/target input. | Read target source or request bounded diagnostic context. | Existing diagnostics and limits answer the question. | Do not batch a single diagnostic or ask Navlyn to build. | Report observed compiler diagnostics. | Claim diagnostics are current after unverified edits or a build ran. |
| Tests | Activate when likely related test files matter. | `navlyn_tests_for_symbol` or `navlyn_tests_for_diff`. | Symbol anchor or actual diff. | Read candidate tests; invoke normal test tooling separately if requested. | Candidate set is sufficient for inspection. | Do not present candidates as executed tests. | Report static test-candidate evidence. | Claim a test passed or covers behavior. |
| DI | Activate for supported dependency-injection source patterns. | `navlyn_di` graph, registrations, or impact mode. | Mode; project or target/query inputs as required. | Read registrations/consumers or inspect another bounded mode. | Relevant source patterns are visible. | Do not treat service registration as runtime container proof. | Report discovered source registrations and edges. | Claim effective runtime resolution or lifetime. |
| Routes | Activate for source-defined ASP.NET Core route patterns. | `navlyn_routes` map or impact mode. | Mode; route pattern for impact. | Read endpoint/auth source facts. | The requested route pattern evidence is present. | Do not infer deployed route tables or effective authorization. | Report static endpoint/auth patterns. | Claim runtime authorization or secret values. |
| Options/config binding | Activate for source-defined options registration and binding. | `navlyn_options` graph or impact mode. | Mode; query for impact. | Inspect a bounded binding/consumer result. | Source relationships answer the configuration question. | Do not ask it to reveal effective values or secrets. | Report code-level binding and consumer facts. | Claim deployed configuration values. |
| Messages/handlers | Activate for supported handler declarations or message call sites. | `navlyn_messages` handlers or flow mode. | Mode and message target. | Read selected handler or call-site source. | Relevant static handler/flow facts are returned. | Do not infer broker delivery or runtime dispatch. | Report source-level handler and call-site evidence. | Claim message execution or delivery. |
| EF | Activate for supported EF Core model source patterns. | `navlyn_ef` model or impact mode. | Mode and entity/target input as required. | Read entity, context, or query-site source. | Needed source-level facts are present. | Do not infer live schema, state, or query execution. | Report discovered EF source patterns. | Claim runtime model or database facts. |
| Packages | Activate for package reference/namespace usage evidence. | `navlyn_packages` usage or impact mode. | Mode and package name. | Inspect bounded usage/reference results. | Source usage facts answer the question. | Do not substitute for package/security review. | Report project references and source uses found. | Claim compatibility, vulnerability, loading, or license status. |
| Framework entrypoints | Activate when framework-discovered entrypoint patterns matter. | `navlyn_entrypoints` framework mode. | Framework discovery inputs and optional project filters. | Inspect returned static entrypoint chains. | Relevant framework candidates are visible. | Do not treat discovery as runtime reachability. | Report bounded heuristic entrypoint evidence. | Claim an entrypoint executes. |
| Pre-edit | Activate for a concrete, non-trivial semantic edit. | `navlyn_prepare_edit` directly. | Intended target by candidate, query, or exact location. | Read its evidence; request one missing impact/test fact if needed. | Anchor and key risks/unknowns are understood. | Do not make preparation a mandatory checklist for trivial edits. | State bounded pre-edit evidence and uncertainty. | Claim the tool edits or guarantees safety. |
| Post-edit | Activate when target-to-diff mismatch risk needs checking. | `navlyn_verify_edit`. | Saved preflight, candidate, query, or exact location plus actual diff context. | Inspect mismatch or run ordinary build/tests. | Guard result and limitations are understood. | Do not treat mismatch as automatic proof of a bad edit. | Report guard facts for the diff/target. | Claim correctness or test success. |
| Actual diff review | Activate only for an actual Git diff/PR. | `navlyn_review`. | Working-tree/staged diff or base/head refs. | Focus on one related test or context fact if needed. | Review evidence answers the review question. | Do not use it for symbol-only explanation. | Report bounded changed-symbol and risk evidence. | Claim approval or runtime correctness. |
| Bounded context escalation | Activate only when ordinary reads and smaller facts are insufficient. | `navlyn_context_pack` with a concrete goal/target. | Query, candidate, or diff and useful scope/budget. | Read selected files normally. | The reading queue is enough to continue. | Do not use as initial discovery or an exhaustive file list. | Provide a bounded reading plan. | Claim complete repository coverage. |
| Batch optimization | Activate only for at least two already-selected supported facts in one workspace. | `navlyn_batch` with the selected logical requests. | Two or more supported requests; anchors already known. | Resolve dependent facts within the returned evidence. | All requested facts or per-request failures are clear. | Do not batch one fact, initial discovery, or a checklist. | Report each bounded request result. | Claim atomic success when individual requests fail. |
| Text-only and ordinary-tool cases | Do not activate when text/files/Git/build/test tools answer directly. | Use ordinary read, `rg`, Git, build, or test tool. | The relevant file, text, diff, or command. | Use Navlyn only if a semantic uncertainty emerges. | Text task or requested execution is complete. | Do not invoke Navlyn for comments, strings, docs, arbitrary text, formatting, or execution. | State what ordinary evidence showed. | Invent semantic certainty from a text match. |
